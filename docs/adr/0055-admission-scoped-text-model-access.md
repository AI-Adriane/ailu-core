# ADR 0055 — Admission-scoped authorization of text models

- Status: Proposed, with the 2.8.0 draft (see the CHANGELOG). The additive engine boundary is described here; application rollout and package publication are separate decisions.
- Context: a host application that keeps a tenant-wide text-model catalog needs the engine to enforce it. A provider key or a model-picker entry is not authorization to invoke every model that provider serves.

## Decision

The trusted host supplies an immutable `textModelAccess` snapshot alongside independent `tenantId` and run identity. Schema 1 carries `tenantId`, `runId`, `policyId`, positive integer `policyVersion`, `catalogRevision`, `policyHash`, and exact `{provider, modelId}` `allowedModels`. Empty is deny-all. The host must create this from authenticated admission and durable policy state; user bodies, prompts, tools and agent results are not authorization sources. The hash is integrity metadata, not a signature or proof of the host's authority.

The policy hash is SHA256 of UTF8 JSON with the ordered fields `{schemaVersion:1,catalogRevision,enabledModels}`. Identities have ordered fields `{provider,modelId}` and are sorted by provider then modelId using JavaScript binary UTF16 comparison, not locale sorting. Duplicate identities are invalid. Rust reproduces that ordering with `encode_utf16`. Unknown fields, invalid version/hash or a different tenant/run are refused. The SDK and bridge use the same snapshot on catalog runs, native builder instances and standalone `invokeModel` calls. Builder compilation accepts an optional `{tenantId,textModelAccess}` admission context; that instance must be run with the corresponding explicit runId.

`DefaultLlmGateway` checks the exact **effective** model after the adapter's pure default-model resolution, before media resolution and provider `complete`/`stream`. Anthropic, Gemini and OpenAI-compatible adapters expose that same resolution through an additive, defaulted adapter method. A placeholder cannot authorize an unlisted default. An explicitly authorized, known default may execute. The policy does not select a replacement model, broaden a pin/council, resolve credentials or waive a spend/approval/security gate. Each call, including retries and middleware calls through the gateway, is checked. Custom adapters must report any model substitution through `effective_model`; an arbitrary external adapter or server is a trusted implementation, not cryptographically attested by the allowlist.

Agents, map-agent spawns and registered subgraphs are built with the same run policy. A host tool that independently invokes another engine/model is a new host boundary: the host must propagate an authorized admission and cannot rely on the parent gateway to constrain unrelated host I/O.

Embeddings, non-LLM reranking, PII and compression use separate capability seams. No request flag exempts a text `complete`/`stream` call by claiming it is non-text. LLM-based judges/rerankers remain text calls when routed through this boundary. The provider/model tuple identifies the logical adapter/model, not immutable weights behind a mutable provider alias or custom endpoint.

## State and compatibility

The frozen `GraphState` DTO is unchanged. Governed JSON state views add `textModelAccess` outside agent channels: final `state`, record-mode `entryState`, and host checkpoint `graphState`. The host must retain the entire view. Resume, approve, signal and replay check the supplied snapshot against that binding before driving the runtime. Missing or replaced metadata is refused; a newer policy cannot enlarge an admitted run. The host also needs a durable governance-mode marker: if it loses both state and top-level metadata, the engine cannot distinguish that loss from an intentionally legacy OSS run.

Legacy calls with no policy remain compatible. Native capability functions explicitly advertise schema 1: NAPI `textModelAccessVersion()`, Python `text_model_access_version()`, and C `ailu_text_model_access_version()`. The TypeScript SDK refuses policies or governed state on older addons, which otherwise ignore unknown JSON fields. New source compiled locally is not evidence that a published addon or deployed worker supports this boundary. The TypeScript public `textModelAccessVersion(): 1 | undefined` and Python `text_model_access_version()` query the actually loaded addon, never the SDK package version. Python catalog, builder and standalone wrappers expose additive `tenant_id` / `text_model_access` keywords (and `run_id` for standalone). Python optional `None` means absence; an explicit JSON null in raw specs or durable state is still present and must refuse. Legacy raw convenience `runPrebuilt` / `runComponent` entries have no admission envelope and explicitly reject `textModelAccess` with `text_model_access_unsupported_entry`; use the catalog bridge for governed agents/components. No claim of whole-application rollout follows from this increment.

The provider gate applies to live and recording invocations. Replay first checks the original state binding, then serves already-recorded decisions without any new provider call. It does not re-authorize a recorded model selection; graph, journal and snapshot remain trusted, integrity-checked host artifacts, not authenticated merely by the policy hash.

Errors at the boundary use stable strings `text_model_access_denied`, `text_model_access_invalid` and `text_model_access_snapshot_mismatch`, without request/policy contents. Agent failures keep the existing error-as-data convention; invalid admission metadata rejects the entry before runtime. A request already admitted keeps its snapshot; ordinary policy changes do not cancel provider I/O already in flight. Emergency revocation, live credential/security checks and admission/worker persistence are separate host responsibilities. Provider credentials are captured when the gateway is constructed for the run; deleting a key from the host database does not prove that later calls in that already-admitted run stop. Provider-side revocation is distinct. This increment adds no instantaneous local key revocation mechanism.

## Validation and release

Offline tests exercise strict snapshots, default resolution on real adapters with fake ports, deny-all, complete/stream with zero denied I/O or deltas, checkpoint metadata, scope and resume/replay mismatch, legacy behavior, native SDK catalog/subgraph/builder calls, Unicode cross-language hashing, standalone calls and older-addon refusal. The host writer remains unavailable until the compatible engine/SDK is published, pinned, propagated to workers and every relevant text surface is covered. No package, tag or production activation is published by this change.
